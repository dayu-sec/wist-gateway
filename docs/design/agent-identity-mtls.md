# agent 身份与恢复（mTLS）

## 1. 目的与范围

本文档细化 [`gateway-access-security.md`](./gateway-access-security.md) §5「agent 的身份」中标注为
**【待做】**的那条：**网关认 agent 从「库里的 bearer 凭据」改为「CA 签的客户端证书（mTLS）」**，
并给出：

- 双向身份的载体与不变式；
- **库丢失 / 换网关后的自动恢复**（不需要逐台人工 `enroll`）；
- 私钥丢失（agent 侧）与锚丢失（网关侧）的**代价边界**；
- 迁移与验收。

> 服务端身份（域名 + 每客户 CA + KMS/HSM）已在 `gateway-access-security.md` 定稿，本文不重复。

> **标注约定**：**【现状】** = 代码已具备；**【待做】** = 本方案要求、今天还不具备。

---

## 2. 问题：为什么现在是「全队手工」

**【现状】**

- agent 身份 = 网关库里一条 **bearer 凭据（哈希）**。库一丢 / 换网关（另一套库）→ 所有凭据
  **查无此证** → 全队 401，且 agent **拿不出可独立验证的身份**来自证。
- agent 侧注册是幂等的：`ensure_enrolled` 见到 state 里已有身份就**跳过注册**
  （`ExistingStateIdentity`），只在凭据**临近到期**时尝试续期；**凭据被拒不会回退去重注册**。
  → 表现为**静默卡死**，只能逐台删 `state/agent_runtime.json` + 人工发 token（O(N)）。
- 续期还会**换发新凭据**（新 id + 新 token）→ **数据库备份越旧，恢复后要人工 `enroll` 的机器越多**。

**根因**：身份载体是「服务端库里的记录」。服务端把它丢了，客户端无法自证。

---

## 3. 目标与不变式

- **身份 = 证书**：agent 持有由 **CA 签发的客户端证书**，网关 **只验链**就能认出它是谁；
  库退化为「登记 + 附加状态」的缓存，而不是身份本身。
- **库可丢**：库丢（CA 不变）时，agent 仍持有效证书 → 网关**首触即重建登记**（零人工）。
- **两把根、各自稳定**：**服务端 CA 根**（下发为 agent 的 `trust_bundle`）与 **agent CA 根**（只留服务端，用于验 client）长期不变（私钥都在 KMS/HSM）；叶证书与客户端证书轮换对另一端透明。
- **不变式**：`agent_id` 是机器标识的**稳定哈希**（【现状】已如此）→ 重建登记**不会产生重复 agent**，
  `work-{agent_id}-{family}` 也不变。

## 4. 证书体系

| 决策 | 说明 |
| --- | --- |
| **用哪把 CA** | **独立 `agent-ca`（决定）**：专用于签 agent **客户端证书**，与签服务端叶的客户 CA **分开**。理由见 §4.1。代价：每客户两把 CA |
| **密钥就地生成** | agent 首装时**本地生成密钥对**（私钥不出那台机器）→ 只把 **CSR** 交上去 |
| **客户端证书形态** | `basicConstraints=CA:FALSE`、`keyUsage=digitalSignature`、`EKU=clientAuth`；身份承载 **URI SAN**（见 §4.2），`CN` 仅留人类可读标签 |
| **有效期** | 客户端证书 **37 天**（保底 30 天 + 7 天提前量，见 §4.2）；服务端叶 ~397 天；两把根 10 年 |
| **刷新依据** | **上一张客户端证书**（链式续期，无宽限），沿用同一设备密钥；窗口见 §4.2 |

### 4.1 为什么用独立 agent CA（决策）

| 维度 | 共用一把客户 CA | **独立 agent CA（采用）** |
| --- | --- | --- |
| 验 client 的根 | 必须下发到每台 agent（`trust_bundle`） | **只留服务端**，不下发给 agent |
| 密钥职责 | 一把私钥签两种用途 | 两把私钥分离（可用不同 HSM 策略 / 轮换节奏） |
| 轮换 | 动 CA = 两个方向一起动 | 可只轮换 agent CA（只影响 client 侧） |
| 策略 | 只能一套（寿命/约束共享） | agent CA 可更短寿命 / 更窄约束 |
| 代价 | 少一套 CA | 每客户两把 CA：配额 / 备份 / 签发流程翻倍 |

判据：**“验 client 的根不出服务端”** 与 **“两套密钥/轮换策略要分家”** 任成立其一，就应独立。本次按独立落地。

### 4.2 客户端证书的承载、有效期与刷新窗（决策）

**承载：URI SAN（决定）**

客户端证书的身份放 **URI SAN**，形如：

```text
spiffe://<tenant_id>/<environment_id>/agent/<agent_id>
```

`CN` 只放人类可读标签（如 hostname），**不作权威**。理由：

| 方案 | 取值 | 工具链 | 网关代价 |
| --- | --- | --- | --- |
| DN（CN） | 要处理 RDN 转义 / 顺序 / 编码差异，多值易歧义 | 都支持 | 需 x509 解析库 |
| **URI SAN（采用）** | 单值字符串，无转义 | openssl / step-ca / 云 PCA / HSM 都支持 | 需 x509 解析库 |
| 自定义扩展 | 自造 OID + 自写 ASN.1 | **可能被中间工具链丢弃** | **自写 ASN.1** + x509 解析库 |

关键判据：**网关无论如何都要新增一个 x509 解析库** —— 现有 `webpki::EndEntityCert` 只能验链、
取 SPKI（`src/api/install.rs:456` 即以此取 SPKI pin），**取不到 Subject/SAN**。既然三种方案的
解析成本一样，就选最标准的 SAN，而非自造扩展。配套约束：
`basicConstraints=CA:FALSE`、`keyUsage=digitalSignature`、`EKU=clientAuth`。

**CSR 只贡献公钥，主体由网关填充**：agent 提交 CSR，网关**忽略 CSR 里的主体**、用自己的
`agent_id`（机器标识的稳定哈希，`src/api/enrollment.rs:109`）生成 SAN 再签发 —— 这样 agent
无法伪造他人的 `agent_id`，§3 的稳定哈希不变式也得到保持。

**有效期**

| 证书 | 建议 | 依据 |
| --- | --- | --- |
| 客户端证书（agent） | **37 天** = 保底 **30** + 提前 **7** | 不变式：**任何时刻剩余 ≥ 30 天**（见「刷新窗」）；上限仍受吊销时效约束 |
| 服务端叶（网关 TLS） | **~397 天** | CABF 上限；轮换对 agent 透明（agent 只信根，不信叶） |
| 两把根（服务端 CA / agent CA） | **10 年** | 只在 KMS/HSM；换根须留**重叠期**（先下发新根，再用新根签） |

**刷新窗**

- **不变式（保底）：任何时刻剩余有效期 ≥ 30 天** → agent 断连 30 天内回来都能续上，不会过期。
- 触发：剩余 ≤ **30 天**时续期。因有效期 **37 天**（见上表），等价于**签发后第 7 天**起可续。
- 常态节奏：换出的新证满 37 天，很快又落到「剩余 ≤ 30」→ 等价**每 7 天续一次**。
  想降频就调大有效期：**V=60 ⇒ 第 30 天起、每 30 天续一次，保底仍是 30 天**（保底 = 有效期 − 起续日）。

  ```text
   签发                   起续期               到期
  day0 ─────────────────── day7 ───────────── day37
                             │  剩余 ≤ 30 天即续
  不变式：任何时刻剩余 ≥ 30 天 → 断连 30 天内回来都能续
  ```

- 凭据：**上一张客户端证书**（链式续期），**不引入 token** —— 否则又回到 O(N) 人工。
- **无宽限**：证书一旦过期即不能再续 → **带 token 重装**。故离线容忍就是硬保底 **30 天**
  （断连 ≤ 30 天必能续；> 30 天 → 过期 → 重装）。
- **续签要留痕**：每次续签的**结果与状态**（成功/失败、新到期时间、下次续签）都要落本地 state
  并**上报网关**（见 §5.5）—— 续签是后台动作，不记录就等于又变成静默。
- 密钥：**沿用同一设备密钥**（只换证书、不换密钥）；`agent_id` 不变。
- 抖动：窗口内**随机化**重试，避免网关重建后惊群。
- `notBefore` **回拨 5 分钟**，容忍两端时钟偏差。
- 残留风险：可自我续期意味着**私钥一旦泄露即长期立足点**。缓解靠三条叠加：
  ① 仅「剩余 ≤ 30 天」窗内可续；② 短命；③ 状态表吊销（§5.6）。

## 5. 注册与恢复流程

### 5.1 首次注册（带 token，一次性）

一次性 token → agent 生成密钥对并提交 **CSR** → 由 **agent CA** 签出**客户端证书**（另下发**服务端 CA 根**作为 agent 的信任锚）
→ 库登记。等价于现有 enroll 流程的扩展（【现状】契约字段已预留：
`CredentialBundle.certificate` / `private_key_ref` / `ca_bundle`）。

### 5.2 日常

agent 走 **mTLS**（出示客户端证书）→ 网关 `WebPkiClientVerifier` 验链 → 身份取自证书
→ 库查/建附加状态。

### 5.3 库丢失 / 换网关（**关键：自动恢复**）

- agent 仍持**有效客户端证书** → 网关 **首触重建登记**：以证书 URI SAN 里的 `agent_id`
  映射（稳定哈希）→ 建回记录。
- **不需要 token、不需要人工、不重装。** 这是本方案的核心验收点，也是「根治」在
  `gateway-access-security.md` §5 里那句「换网关后：自动，零人工」的落地形态。

### 5.4 被拒 / 过期的语义（不再静默卡死）

**过期由 agent 本地自检，不靠服务器信号。** 证书过期时 rustls 在**握手期**就回 TLS alert
`CertificateExpired`（`rustls-0.23.45/src/error.rs:635`），HTTP 层根本收不到请求，服务器**给不出**
任何 401 错误码；agent 侧只看到不透明的握手错误（`AlertReceived`，`error.rs:69`）。因此
**agent 自己读本地证书的 `notAfter` 判定**（它本来就要引 x509 解析库，§4.2）：

| 本地判定 | agent 行为 |
| --- | --- |
| 剩余 ≤ 30 天 | **续签**（链式，§4.2） |
| 剩余 ≤ 0（已过期） | 置「**需重装**」状态并**上报**；**停止无谓重试**（不静默卡死） |

**网关侧**只需对**能拿到请求**的两种拒绝给可辨识错误码：

| 错误码 | agent 行为 |
| --- | --- |
| `unknown_credential`（CA 可信但未登记） | **自动重建登记**（§5.3） |
| `certificate_revoked` | **明确报错退出**（不静默重试） |

### 5.5 续签的可观测性（要求）

续签 / 过期是后台动作，**不记录就等于静默**：

- **agentd**：每次续签把 `{结果, 旧/新到期时间, 错误}` 落本地 state，并作为状态**上报**网关；
- **gateway**：续签记审计（`audit credential_renewed …`），并把**证书状态**（有效期、上次续签时间）
  入库，页面上每台 agent 可见（对齐「新装机没数据也能从页面看出原因」的诉求）。

### 5.6 吊销（为什么必需、怎么做）

**存在，而且必要** —— 触发场景：

| 场景 | 说明 |
| --- | --- |
| agent 私钥泄露 / 机器被入侵 | 攻击者持有证书 + 私钥，可冒充该 agent |
| 机器退役 / 下线 | 不想让它再连、再接收工作 |
| 异常 agent 隔离 | 立即切断 |

**为什么「停止续签」不够**：续签的凭据就是**旧证书本身**（§4.2）。持有私钥的攻击者可以
**自己续签续命**，永远不会过期 —— 所以必须有一个**能立即生效、且跳续签持续**的拒绝点。

**做法：网关侧按 `agent_id` 的拒绝名单（状态表）**

- 拒的是 **`agent_id`**（不是证书序列号）：攻击者续签 / 重签都还是同一个 `agent_id` → **仍被拒**；
  它若伪造机器标识换 `agent_id`，就变成**新身份**，得走首注册（需 token）→ 拿不到原 agent 的授权。
- 生效点：`ClientCertVerifier` 验链后查名单，命中即拒。
- **列表 GC**：条目只需保留到**那张证书自然过期**为止（≤ 有效期），过期即清 —— 列表不会无限增长。
  这正是「短命证书 + 状态表」的组合意义：**不是二选一**（短命负责封顶时效，状态表负责立即切断）。

**为什么不用 CRL / OCSP**：验签方只有网关自己（agent CA 也在我们手里）。CRL 要分发、OCSP 要
实时联网到 CA —— 客户内网 / 离线场景不可达。状态表内置在网关里，零外部依赖，规模也只到
每客户 10²–10³ 量级。且因 agent CA 与服务端 CA 分开（§4.1），吊销只影响 client 侧。

## 6. 代价边界：谁丢了，付什么

| 丢失方 | 后果 | 代价 |
| --- | --- | --- |
| **某台 agent 的私钥/证书** | 该机无法自证 | **单机**重装一次（带 token），**不影响全队** |
| **网关 CA 私钥**（锚） | 它签的双端证书全部失效 | **全队**重装 → 私钥必须**外置且持久**（KMS/HSM，见 §4） |
| **网关库** | 登记丢失 | **自动重建**（mTLS 生效后，§5.3） |

一句话：**agent 私钥是耗材（丢=单机重装）；网关 CA 私钥是唯一不可重建的资产（丢=全队重装）。**
这正是 mTLS 的价值：把「密钥丢失」的代价**限定在丢失的那一端**。

## 7. 迁移与兼容

- **现状差距**：agentd 只支持 `bearer scheme`（其它直接拒）；网关 TLS 目前是
  `ServerConfig::builder().with_no_client_auth()`。
- **双轨期**：bearer 路径继续可用；新装 / 重注册走 mTLS；提供一次性迁移（重 enroll 换证书）。
- **一次性成本**：现有 agent 需**重注册一次**（任何方案都躲不掉 —— 当前锚/身份已经变过）。
  但因 `agent_id` 是稳定哈希，**不会产生重复 agent**。
- **过渡缓解（便宜，先做）**：备份保持**小时级**；或让**续期不轮换 token**（旧 token 短期共存）。
  两者都能把「要逐台动手」的尾巴缩小到很小。

## 8. 实现拆分

**wist-agentd**

- 本地生成 / 保存客户端密钥对；mTLS 客户端配置（出示客户端证书）；
- **周期性续期 + 本地有效期自检**：今天续期只在 daemon **启动时**评估一次
  （`src/control/runtime_entry.rs:524`），需补定时任务（§4.2）；过期判定靠**本地读 `notAfter`**（§5.4）；
- **续签留痕与上报**：续签结果 / 证书状态落 state 并上报（§5.5）；过期置「需重装」并上报；
- 收到 `unknown_credential` 时**凭现有证书自动重建登记**；`revoked` 明确报错；
- `enroll --force`（丢弃本地身份、凭 token 重新注册）——现已缺失，是「重装 ≠ 重注册」的补口。

**wist-gateway**

- **独立 `agent-ca`**（决策）：网关维护其根作为 **client 验证信任库**；TLS 开启
  `WebPkiClientVerifier`（只验链，不再依赖库里的 bearer 记录）；
- **首触重建登记**（证书 URI SAN → `agent_id`）；
- mTLS / 签发路径需引一个 x509 解析库（现有 `webpki::EndEntityCert` 取不到 Subject/SAN，见 §4.2）；
- **续签审计 + 证书状态下库**（有效期 / 上次续签），供页面展示（§5.5）；
- **按 `agent_id` 的拒绝名单**（§5.6）：`ClientCertVerifier` 验链后查名单，命中即拒；条目随证书过期 GC；
- 签发接口（CSR → 客户端证书）；401 **错误码区分**。

## 9. 验收

1. **清空网关 store（保留 CA）** → agent **零人工**、≤1 个轮询周期内自动重新登记上线。
2. 换域名 / 续期服务端叶证书 → agent 无感。
3. 轮换 / 吊销某 agent 证书 → 被拒且**报错明确**；未过期者可续签恢复，已过期者**明确提示需重装**。
4. 重装（私钥丢失）→ **单机**恢复，且 `agent_id` 不变（稳定哈希）。
5. 续签 / 过期状态**可从页面与本地 state 看到**（不是静默）：续签成功留痕、过期显示「需重装」。
